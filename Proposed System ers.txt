Proposed System Title

School Event Attendance and Session Completion Management System

A web-based system that allows school personnel to create events and sessions, register participants, record attendance, monitor session completion, and generate reports.

1. Users

Use 2 main roles to satisfy the minimum requirement.

User Role	Main Responsibilities
Administrator / Event Coordinator	Manage users, events, sessions, registrations, attendance, completion status, and reports
Student / Participant	Log in, view available events and sessions, register for events, view attendance, and check session completion
Optional third role

Attendance Staff – can scan/record attendance and update session completion but cannot manage users or system settings.

4. Important Business Rules

You need at least 3 meaningful business rules. I recommend these 6:

Business Rule 1 — Registration

Only registered participants can have attendance records for an event session.

Example:

Student A is not registered for Event 001 → Student A cannot be marked present.

Business Rule 2 — Duplicate Attendance

A participant can only have one attendance record per session.

So the database should prevent:

Student 1001 + Session 001 + Present
Student 1001 + Session 001 + Present

from being entered twice.

Business Rule 3 — Session Completion

A participant can only be marked as completed when their attendance satisfies the session requirement.

For example:

Present = eligible for completion
Late = eligible for completion
Absent = not eligible
Excused = subject to coordinator approval

Business Rule 4 — Event Capacity

The number of confirmed registrations cannot exceed the event capacity.

Example:

Capacity = 50
Confirmed participants cannot become 51.

Business Rule 5 — Session Schedule

A session must belong to an existing event and its schedule must fall within the event schedule.

Business Rule 6 — Account Security

Passwords must be stored using secure password hashing and never as plain text.

18. Security Requirements

Your implementation should visibly satisfy these:

Password

Never store:

password = "12345678"

Store a hash instead:

$2y$10$................................

For PHP, use:

password_hash($password, PASSWORD_DEFAULT);

and:

password_verify($password, $storedHash);
Role Protection

Example:

Student
→ Events
→ My Registration
→ My Attendance
→ My Completion

Admin
→ Dashboard
→ Users
→ Events
→ Sessions
→ Registrations
→ Attendance
→ Completion
→ Reports
→ Audit Logs

A student must not be able to manually open an admin page just by changing the URL.
